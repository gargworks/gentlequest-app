## 1. The Audit (Value Capture vs Creation)

We simulated three economic models to find the one that aligns with "Sovereignty".

### Model A: The "Apple Tax" (30% Commission)
*   **The Pitch:** We charge 30% on every paid agent install.
*   **The Simulation:**
    *   Developers hate it (too small scale).
    *   Users avoid it (friction).
    *   Result: **Dead Ecosystem.**
*   **Verdict:** ❌ REJECTED.

### Model B: The "Spotify Bundle" ($20/mo Subscription)
*   **The Pitch:** Users pay one price, we distribute to agents based on usage.
*   **The Simulation:**
    *   Requires central tracking (Anti-Sovereign).
    *   Validates "Rent-Seeking" behavior (Agents optimize for clicks, not value).
*   **Verdict:** ❌ REJECTED.

### Model C: The "Context Economy" (Context as Currency)
*   **The Pitch:** The platform is free. The *Leverage* is Context.
*   **The Mechanic:**
    *   **For Devs:** A standalone script is worth $0. A script that can read your `obsidian_notes` (with permission) is worth $1,000. Nucleus is the *only* safe way to get that access.
    *   **For Users:** You pay with "Trust" (and eventually money to the dev directly). Nucleus takes $0 cut.
    *   **For Nucleus:** We capture value via **Enterprise Governance** (SSO, Audit Logs) later. The "Individual" version is the "Get Hooked" layer.
*   **Verdict:** ✅ ACCEPTED.

## 2. The Incentive Structure

*   **Developer Incentive:** Access to the **Trust Graph**. "If I publish on Nucleus and get verified, I get access to the user's high-value context."
*   **User Incentive:** **Safety Assurance.** "I only install via Nucleus because I know it won't steal my SSH keys."

## 3. The "Token" Definition

We are NOT creating a crypto token.
The "Token" of the network is **Verified Reputation**.
*   High Reputation = High Context Access.
*   Low Reputation = Sandboxed Isolation.
