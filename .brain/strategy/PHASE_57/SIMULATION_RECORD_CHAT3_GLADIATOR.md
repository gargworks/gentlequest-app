## 1. The Threat Modeling (Porter's Five Forces)

We pitted the "Trust Broker" strategy against the inevitable market responses.

### Threat A: "The Sherlock" (OpenAI/Google Agent Store)
*   **The Attack:** OpenAI launches an "Agent Marketplace" integrated into ChatGPT. It is slick, fast, and free.
*   **The Vulnerability:** Nucleus users might migrate for convenience.
*   **The Defense (Counter-Positioning):** **Sovereignty.**
    *   OpenAI's goal is Data Ingestion (Cloud-First).
    *   Nucleus's goal is Data Protection (Local-First).
    *   *The Wedge:* Corporate IT will block "OpenAI Agents" that scan internal DBs. They will *require* a local governance layer. Nucleus is that layer.

### Threat B: "The Commodity Fork" (Open Source Copycats)
*   **The Attack:** Someone forks `nucleus` and removes the "Annoying Permissions".
*   **The Vulnerability:** Users prefer "Zero Friction" and install the unsafe fork.
*   **The Defense (Network Effects):** **The Web of Trust.**
    *   A fork has no Reputation Graph.
    *   If you install a "Wild" agent, you are unprotected.
    *   If you install a "Nucleus" agent, you inherit the `TrustGraph` of the community.

## 2. The Strategic Power (Helmer's 7 Powers)

Where is the moat?

### Power 1: Switching Costs (High)
*   Once a user has curated their **Local Trust Graph** (which agents can see which secrets), moving to a new platform requires re-auditing everything.
*   *Action:* We must make the `TrustProfile` portable but deeply integrated into the OS.

### Power 2: Cornered Resource (The Edge)
*   We own the **Local Runtime** (RAM, CPU, Filesystem). Cloud providers only own the API.
*   We can run *during* an internet outage. They cannot.
